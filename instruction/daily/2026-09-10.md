## ⭐ 供电过流根因 &「全部外设重启」排查（重点）

### 现象
- 09-09 夜~09-10 出现多次「全部外设同时重启」：所有 USB 设备掉线重枚举、/dev/ttyUSB*/ttyACM* 端口号反复洗牌（雷达 ttyUSB0↔1↔2、OpenMV ttyACM0↔1↔0、扫码枪 ttyACM0↔1↔2）；camera/scanner 节点挂在旧端口后全部失效。

### 证据（journalctl 内核日志）
- 09-10 00:14–00:15：hub（Terminus 1a40:0101）下键盘/Logitech 三次整体 disconnect→再枚举
- 09-10 09:27:06：**所有 USB 端口同时报 `over-current change #1`** → 雷达 4-1/4-2、hub 2-2 全掉，随后逐个重枚举
- 09-10 09:31:24：`over-current change #2`（**当时仅雷达一个耗电设备在跑**，恰逢 rplidar 电机 `Start`）
- 09-10 09:40:28：雷达换 4-2 口 + 单独 SLAM，电机启动瞬间再次全总线 disconnect
- 端口漂移时间线：雷达 ttyUSB0→1→2→1，扫码枪 ttyACM0→1→2，OpenMV ttyACM1→0→1

### 根因（确认）
- **树莓派 USB 供电能力不足**。RPLIDAR C1 电机启动瞬时电流超过 xHCI 单口/总线供电上限 → 触发 USB 总线级 `over-current` 保护 → 整条 USB 断电重枚举。
- 换任意 USB 口（含直连 4-1/4-2）均无效，换端口不是解药。

### 验证与临时方案
- **拔掉 OpenMV、减少外设后不再过流**：`/scan` 稳定 10Hz、过流 0 次、三模块（雷达+扫码+已拔 OpenMV）并行无异常。
- 当前可用组合：**雷达 + 扫码枪**（OpenMV 可临时接入，但增加过流风险）。
- 根治方向（硬件，待做）：

## 经验与排障技巧

- **`pkill -f '关键词'` 会匹配到执行命令的 bash 自身 cmdline**（参数含同一字符串）导致自杀/挂死、目标未杀——清场应改用 `kill -9 <明确PID>` 或避开自匹配
- 后台进程启动模式：`source <ROS setup> && setsid python3 start.py <fn> > /tmp/<fn>.log 2>&1 < /dev/null &`，可脱离会话后台运行
- `ros2 service call` 偶发 `rcl node's context is invalid`：用 python rclpy 客户端（`wait_for_service` + `spin_until_future_complete`）兜底验证服务往返
- openmv_msgs 接口需 `source ~/ros2_ws/install/setup.bash` 才能被 ros2 CLI 解析（否则 `The passed service type is invalid`）
