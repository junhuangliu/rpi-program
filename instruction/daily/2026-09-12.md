### 任务记录（STM32 串口闭环验证 & NUL 帧尾修复）
- 需求：确认 STM32 发命令能否回传。给 `bridge.py` 增加调试日志：
  - `read_loop` 在 `-d` 时打印 `[RX] <收到行>`；`_reply` 在 `-d` 时打印 `[TX] #RES,...`；未知命令 `-d` 时打印 `text=... fields=...`
- 实测发现：STM32 发 `#QRB$` → 第一次回传 `#RES,UNKNOWN:QRB$`
  - 排查：`[RX] 未识别命令: text='#QRB$\x00' fields=['QRB$\x00']` → **STM32 帧尾 `$` 后带 NUL 字节 `\x00`**，`endswith("$")` 判断失败、命令匹配不上
  - 修复：`read_loop` 解析前 `text.replace("\x00", "")` 剔除 NUL
- 修复后实机验证通过：
  ```
  [RX] #QRB$
  [TX] #RES,12462213$
  ```
  bridge 调 `/scanner/query_parsed`（返回 `12462213`）并回传 STM32 成功
- 提醒：bridge 后台重启须用精确 PID kill（`ps | awk` + `kill -9`），`pgrep -f 'start.py bridge'` 会自匹配导致 shell 挂死

### 任务记录（bridge #POS 修正：整车初始系 + 角度 ±π 归约）
- 问题 1：初始角度应为 0，实际 3.14（base_link 相对 map 初始 yaw=π，因 laser→base_link 静态 TF 固定绕 z 180°）
- 问题 2：角度绕一整圈跑到 0~2π，需归约到 [-π, π]
- 根因：`map→base_link` 初始 yaw = laser_scan_matcher(0) + 静态 TF(π) = π；`(yaw-yaw0)` 未归约
- 改动 `fun/bridge.py` on_pos_timer（方案 B 整车初始系）：
  - 首次有 TF 时记录 origin `(x0,y0,yaw0)`（此时 yaw0=π），之后：
    - 位移旋转到初始系：`x_f = dx·cos0+dy·sin0, y_f = -dx·sin0+dy·cos0`
    - 角度 `yaw_f = -atan2(sin(yaw-yaw0), cos(yaw-yaw0))` → **[-π, π]**，初始 0
- 验证：bridge 日志 `记录整车初始位姿: yaw0=3.142`；启动即 `[TX] #POS,0.001,0.000,0.000$`；与 `tf2_echo` 换算一致
- 说明：SLAM 重启后 origin 会失效（map 重建），需重启 bridge 复位 origin（文档已标注）
- 当前命令表：TASK1 / QR / QRC / QRB / QRA / OBS；#POS=整车初始系，坐标正负与初始角已修正
