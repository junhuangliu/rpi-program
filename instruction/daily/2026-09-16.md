# 2026-09-16 会话日志

## 蓝牙 BLE 连通性验证（最终放弃）

### 目标
实现 OpenMV N6 与树莓派的 BLE 无线通信，替代 USB 串口。

### 已完成
- N6 端 BLE NUS 底层版 main.py 编写（底层 bluetooth API，IRQ 回调，NUS 串口透传）
- 发现并修复多个固件兼容问题：
  - aioble 在此固件不兼容（UUID 在 bluetooth 模块，无 sys.stdout）
  - MicroPython BLE 常量名未导出（用数字事件码替代）
  - gap_advertise adv_data 31 字节上限（去掉 flags 段，名字+服务 29 字节）
  - BLE NAME 长度导致超限（无 flags 组合 29 字节 OK）
  - connectable 默认值（固件默认 True，确认 gap_advertise 支持 connectable 关键字）
- 安装 bleak 3.0.2 + dbus-fast 5.0.22

### 失败原因
btmon 抓包确认 N6 广播的是 **ADV_IND**（可连接），但：
- **树莓派作为 central 连 N6**：Connection refused (111) / 超时
- **N6 作为 central 连树莓派**：连接超时失败（EVT 8）
- **双向均无法建链**

### 根因分析
N6 CYW43439 BLE 固件 v5.0.0 的**连接功能存在缺陷**：
- 广播正常（ADV_IND，名字可见）
- 扫描正常（hcitool lescan 能看到其他 BLE 设备）
- GATT 服务注册正常（无报错）
- **但任何连接请求都不被响应**（作为 peripheral）或**无法建立连接**（作为 central）

### 清理
- 恢复 `openmv_n6/main.py` 为 USB 版
- 删除 `tool/ble_check.sh`、`tool/ble_probe.py`
- 卸载 bleak / dbus-fast
- 项目回到蓝牙方案前状态，继续 USB 串口通信

### 结论
N6 蓝牙连接在当前固件下不可用，保持 USB 串口方案。
