## 里程误差排查（待办）

### 现象
实际向前移动 50cm，上位机显示仅 45.2cm（约 90% 尺度）。

### 分析
显示值 = `map -> base_link` TF，链路 `map--slam_toolbox-->odom--laser_scan_matcher(纯激光ICP)-->laser--静态180°-->base_link`：
- 无轮式里程计，运动完全由激光相邻帧 ICP 估计
- 可能原因：① 纯激光 ICP 系统性尺度欠估（主因）；② slam_toolbox 在线全局优化拉回位姿；③ 慢速小位移被 `kf_dist_linear=0.05` / `minimum_travel_distance=0.1` 吞掉；④ 雷达偏心/噪点/迭代不收敛

### 验证方案（待执行）

  - `odom->laser`≈0.50 而 `map->base`=0.45 → slam_toolbox 在线修正，考虑关回环

## 里程误差排查（已完成）

### 排查过程
- 首版 `tool/check_tf_dist.py`（input 两次快照）两次读到相同 TF → 位移恒 0
  - 根因①：TransformListener 默认 `spin_thread=False`，input() 阻塞期主线程不 spin，buffer 停在同一帧 → 改 `spin_thread=True`
  - 根因②：仍 0。重写为**实时显示模式**（每 0.2s 刷新 odom->laser / map->laser / map->base_link 相对起点位移，回车重置起点）——边推边看，直接暴露真实数据

### 结论（实测数据，直推 50cm）
| 链路 | 位移 | 判定 |
|---|---|---|
| odom->laser（matcher 激光里程计） | 0.504m | ✓ 准 |
| map->laser（含 slam 在线修正） | 0.414m | ✗ 缩水 ~9cm |
| map->base_link（上位机原读值） | 0.414m | ✗ 缩水 |

- **病根 = slam_toolbox 在线建图把位姿吸回**（每帧 scan 对全局地图最优拟合，位移被"宁小毋大"地修正，非固定比例约 -10~-18%）
- matcher 本级激光里程计反而很准 → 计程应读 odom 系
