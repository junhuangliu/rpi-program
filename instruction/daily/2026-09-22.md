## 任务记录（MaixCAM 长连接修复 + 数据链路联调）

### 背景
- 用户查询 MaixCAM 日志位置；`tail -f /tmp/maxicam.log` 报文件不存在

### 日志位置澄清
- MaixCAM 有**两处**日志：
  1. **数据日志**：项目根 `maixcam.log`（`fun/maixcam.py` 每条收到数据追加一行）
  2. **运行日志**：后台启动时 `/tmp/maixcam.log`（rclpy 日志：连接/超时/发布等）
- 易混淆点：正确名是 `maixcam`（maix+cam），误拼 `maxicam` 会另生成 `/tmp/maxicam.log`（内容即 `start.py` 用法提示，因非法功能名打印用法后 `sys.exit(1)` 秒退）

### 秒断根因（本次核心问题）
- MaixCAM 不定时发数据，但 `fun/maixcam.py` 默认 `conn.settimeout(5.0)`：任意连接 **5 秒没收到任何字节**就按"TCP 半开"主动断开（`handle_client` 的 `socket.timeout` 分支）
- MaixCAM 侧显示"连接成功"仅 = TCP 握手完成，不代表服务端收到过数据
- 表现：日志反复 `已连接 → 连接超时，主动断开`，一条 `/maixcam/data` 都没有

### 改动（`fun/maixcam.py`）
- `RECV_TIMEOUT = None`：默认不设 recv 超时 = **持续连接**，数据何时到都不踢；`-t <秒>` 仍可设限制，`-t 0`/缺省 = 不超时
- 连接启用 **TCP keepalive**（`SO_KEEPALIVE` + KEEPIDLE=60s/INTVL=10s/CNT=6）：MaixCAM 掉电/拔线（无 FIN）由内核探测失败后断开，兼顾健壮性
- 启动日志显示 `keepalive 已启用, recv 超时 不超时(持续连接)`；修正 docstring 端口 8080 → 6000
- 验证：`python3 -m py_compile fun/maixcam.py` 通过；`./control.sh stop/start maixcam` 重启生效
